<objective>
Add the ONE byte-neutral capture point the structural data-order proof needs: an optional
`on_draw=None` keyword on `get_batch_memmap_masked` (D-29) threaded through `train()` to both
TRAINING loader call sites (D-30), with tests proving the default path draws identical `ix`, that a
recorder sees every teaching and replay draw in call order, that the stream hash is a function of
seed and bins, and that a resume chain reproduces an uninterrupted run's stream (the property plan
27-03's rung ladder relies on).

Decisions implemented: D-26 (iii), D-29, D-30.

Decision resolutions carried here (visible; the operator may override at execution):
- D-29 resolved per RESEARCH OQ3: `get_batch_memmap_masked` is called only inside `train()`'s
  closures (`loop.py:646-653` teaching, `:691-693` replay), which no driver kwarg reaches, so
  `train()` gains a keyword-only `on_draw=None` passthrough threaded to both sites — `loop.py` is
  not digest-pinned and every golden-trajectory test stays byte-identical when the value is
  `None`. The alternative (rebinding `loop_mod.get_batch_memmap_masked` from the driver) was
  rejected as production monkeypatching.
- D-30's "every draw the loop makes" is read as every draw a TRAINING STEP consumes. There is a
  THIRD `get_batch_memmap_masked` caller, `estimate_loss` (`loop.py:118`), reached only when a CSV
  logger exists (`csv is not None`, i.e. `log_path` was given, `:788`) and `step % eval_interval == 0`
  (`:858`). Its draws sit inside `estimate_loss`'s RNG snapshot/restore (`:105-129`, the
  resume-equality contract) and never move the training stream, so recording them would add eval
  draws no optimizer step consumed and would make the digest depend on `eval_interval`. It is
  deliberately NOT threaded; the `train()` docstring says so, and the coverage test states the
  no-eval precondition it relies on.

Purpose: RELRN-04 says "identical budget and seed" is enforced structurally — the sampler draws
from the global NumPy RNG (`data.py:117`), so the offset stream is the only place data order is
observable, and this hook is the only byte-neutral way to observe it.
Output: two additive edits under `src/personacore/training/`, `tests/test_phase27_on_draw.py`.
Expected collected-test delta: +5 over the 2802 baseline (record the measured count).
