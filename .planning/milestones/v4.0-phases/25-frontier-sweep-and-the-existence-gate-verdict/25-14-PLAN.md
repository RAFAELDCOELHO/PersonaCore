<objective>
Put the machine into a state where a 4.5–6.3 day unattended run can survive logout, sleep and session
end — and record the state it was put into, so it can be put back.

Purpose: the last production run on this machine was killed externally at 60 minutes. `pmset -g` reads
`sleep 1` on AC **and** battery, held off only by transient assertions including stray `caffeinate`
processes from earlier sessions. A macOS compute process holds no idle-sleep assertion on its own, so
without D-12's own `caffeinate -dims` wrapper and D-13's system-level change, the sweep would be racing
a one-minute idle timer for six days.

Two things make this plan different from "start a job". First, `KeepAlive` is **FALSE** on purpose: an
automatic restart would re-enter a point without passing the driver's deliberate resume logic and
would violate D-10, so the agent must not be self-healing. Second, D-43's verification method as
CONTEXT states it does not work — `pmset -g`'s summary line enumerates assertions rather than
processes and was measured over-counting five against three. The read-back must go through
`pmset -g assertions` by owning process.

Output: two LaunchAgent plists, a dated operational note, and the live-watched heartbeat and watcher.
</objective>

| Boundary | Description |
|----------|-------------|
| a privileged system-wide power change → the developer's machine | `sudo pmset -a` alters sleep behaviour for every process; the prior state must be measured before it is overwritten |
