**`def fact_window_span(fact_ids, fact_index, block_size)` -> `(start_element, n_windows)`.**
Pure numpy, no I/O, no torch. It answers "which contiguous run of `block_size`-aligned windows does
this fact own", read from the FACT BIN'S CONTENTS, never from a `cumsum` of padded lengths:
  - window owners are `fact_ids[:-1].reshape(-1, block_size)[:, 0]`
  - `rows = np.flatnonzero(owners == fact_index)`
  - raise `ValueError` naming `fact_index` if `rows` is empty, and raise naming the gap if `rows` is
    not contiguous — a fact whose windows are split is a packing defect, not a draw to serve
  - return `(int(rows[0]) * block_size, int(rows.size))`

This is EXPORTED, not private, and the docstring must say why: plan 21-10's `count_aligned` needs the
same window range in order to observe `per_step_distinct_facts`, and a second copy of this arithmetic
is a second implementation free to drift from the one the loader actually draws through. One function,
two callers.

**`def get_batch_fact_aligned(bin_path, mask_path, fact_path, block_size, device, *, step, n_facts)`.**

Semantics — deterministic, not random. `q = 1`, no subsampling:

  - `y[m == 0] = -100`, unchanged
