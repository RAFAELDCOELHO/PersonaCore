**`math.exp` and `math.sqrt` only — no `erfc`, no Phi, no `log`.** That is what makes it an oracle of
different mathematics rather than a second spelling of `delta_closed`.

Implement the **substituted** form, not the literal one. With `t_min = eps/mu + mu/2` and
`z = t_min - mu = eps/mu - mu/2`, substituting `u = t - t_min` gives exactly
`delta = phi(z) * integral_0^inf exp(-z*u - u*u/2) * (1 - exp(-mu*u)) du`.
The docstring must state this is an **exact algebraic identity on D-13's integral, not a different
integral**, and name the three things it buys: `exp(eps)` never appears so F2's overflow cannot
reach the oracle; the `max(0, .)` clamp disappears because the domain IS the support; and the
non-vacuity test stays non-degenerate where the literal form's silently dies (measured — `trunc/I`
stays ~1e-33 in every F1 row because `I` never underflows, only the `phi(z)` prefactor does).

Numerics, every constant carrying its measurement in a comment:
  - `U = -z + math.sqrt(z * z + 2.0 * lam)` — the exact positive root of `z*U + U**2/2 == lam`.
    Well-defined for all real `z` including negative (ε=0.1, μ=4 gives z = -1.975, U = 14.78), and
    always `U + z = sqrt(z*z + 2*lam) > 0`, which the Mills bound needs. A width rule, not a
    constant: at ε=8, μ=0.5 the integrand dies within U = 4.45; at ε=0.01, μ=8 it needs U = 17.26.
  - **Composite Simpson**, `h = U / (n - 1)`, alternating 4/2 weights, `* h / 3.0`. Not trapezoid:
    Simpson at n=20,001 beats trapezoid at n=400,001 by 3-4 orders with 20x fewer nodes.
  - **The grid starts EXACTLY at `u = 0`** (i.e. at `t_min`). The integrand has a kink there — 0
    below, right-derivative `phi(t_min - mu) * mu > 0` above — and putting the kink inside a panel
    costs up to six orders (measured 3.30e-13 vs 1.07e-06). This is a measured requirement, not
    tidiness; say so in the comment.
  - `lam = 40.0` with its reason: Λ=20 leaves a ~6e-8 relative truncation bound that dominates total
    error; Λ=80/160 buy nothing and cost an order of magnitude in discretisation error at fixed node
    count. `n = 20001` with its reason: **more nodes is not monotonically better** — at n=100,001
    the round-off floor (~6e-14) takes over and three of five measured rows get WORSE. A future edit
    that "makes it safer" by raising `n` is making it worse.
  - `_INV_SQRT_2PI = 1.0 / math.sqrt(2.0 * math.pi)` as a module constant.
