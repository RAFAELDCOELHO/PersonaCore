<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| teaching process → recall process | The adapter file on disk is the only thing that crosses; the boundary is what the clean-room claim rests on |
| recall process → public evidence | `results/` ships publicly and is what a reader checks instead of trusting |
| demo process → browser and network | The offline guarantee must hold with Wi-Fi off |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-18 | Spoofing (of the novel claim) | a fact value reaching a prompt | mitigate | `assert_no_value_in_prompt` aborts the run with `SystemExit`; the human checkpoint additionally spot-checks five committed dumps by hand rather than trusting the guard alone |
| T-14-25 | Tampering | base weights changed during teaching | mitigate | The `snapshot_params` canary raises on any frozen parameter that moved; the run log capturing it is committed |
| T-14-34 | Repudiation | a missed threshold quietly retried until it passes | mitigate | D-12 verbatim, restated in the task action: the miss is recorded unamended before any ship decision, and the refuse-to-rerun guard makes a silent second attempt impossible without deleting named evidence |
| T-14-27 | Information Disclosure | the demo reaching the network | mitigate | Verified empirically at step 13 with Wi-Fi off, an empty cache, and devtools open — the acceptance criterion is an observed empty third-party origin list, not a code inspection |
| T-14-28 | Spoofing | a dead memory toggle | mitigate | Control 3's CPU bit-identity proof plus the on-camera check that the same question yields different answers with an identical token panel |
| T-14-05 | Information Disclosure | personal data in public evidence | mitigate | Every fact value is invented and passed the D-02/D-03 gate; `data/`, `checkpoints/`, `logs/`, and `*.pt` stay gitignored |
| T-14-SC | Tampering | package installs | accept | Zero new packages; the run uses the existing venv |
</threat_model>
