Give Phase 21's fact-aligned loader a path through `train()`, and refuse the configuration where the
aligned corpus is trained through a mismatched accumulation window.

at the only production caller. This plan makes it code in `train()`; plan 22-10 wires the caller.

measured gap this closes: `TrainConfig(...)` at the production caller omits `grad_accum_steps`, so it

prose and 0 times in its code** — so the aligned corpus was being trained at accum=1 with SC2's
"one micro-step = one privacy record" true only in prose. Also state the DP consequence: under
`dp_fn`, `accum` is the `N` in D-02's final divide, so a disagreement here silently changes the
sensitivity story.

**(d) The `batch_fn` branch.** Add a `fact_bin is not None` branch to the dispatch at `:402-452`,
placed so it takes precedence over the mask branch. It must resolve **both** PATTERNS traps:
  - **The absolute step counter is not in the closure.** `step` lives at `loop.py:507` and advances
    in the `while` loop. Capture a small mutable cell defined before the dispatch — e.g.
    `_fact_cursor = {"step": 0, "seen": []}` — and update `_fact_cursor["step"] = step` at the top of
    each `while` iteration, before `_optimizer_step` is called. Comment must say why a closure over
    the loop variable would be wrong (it would capture the binding at definition time, not the value
    at call time) and why the cell is the minimum change.
  - **Three return values against a two-value unpack.** `_optimizer_step:170` does
    `xb, yb = batch_fn(micro)`. The branch's closure calls
    `get_batch_fact_aligned(train_bin, train_mask_bin, fact_bin, model_cfg.block_size,
    runtime.device, step=_fact_cursor["step"], n_facts=n_facts)`, appends the returned `fact_index`
    to `_fact_cursor["seen"]`, and returns `(x, y)` — exactly two values. **Do not change
    `_optimizer_step`'s unpack**; every other `batch_fn` returns two values and widening the contract
    for one branch would touch four call sites for no gain.
  - **The one-record-per-micro-step refusal.** After the accumulation window, refuse (`ValueError`)
    unless the collected `fact_index` values for that step are exactly `n_facts` distinct indices —
    i.e. every fact contributed exactly once. Message names Phase 21 D-02: one micro-step IS one
    privacy record under ragged fact-aligned accumulation, and that claim is what makes ordinary
    backward hand back the per-record gradient. Clear `_fact_cursor["seen"]` at the start of each
    step. This turns SC2's prose into a runtime property at the cost of a list append per micro-step.
