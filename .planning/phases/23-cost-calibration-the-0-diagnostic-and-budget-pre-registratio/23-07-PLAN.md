<objective>
Close WARNING-2: give the production DP driver a real resume path, and prove it reproduces a
bit-identical ε across a kill on MPS.

Purpose: `train()` already implements `resume_from` completely — the three-branch DP-slot matrix at
`loop.py:710-780` is documented at length, WARNING-1 is closed on it, and `22-REVIEW`'s CR-04 was
traced and rejected on measured grounds. What is missing is the one hop above it:
`scripts/teach_persona.py:1379-1414` calls `train(...)` and **does not pass `resume_from`**. Without
it, a killed DP arm — and at n=64 an arm runs ~30 minutes — can only be restarted from zero, and
`refuse_if_exists` will not even allow that without the operator deleting the CSV, which
discontinuities the curve `loop.py:795-799` derives cumulative tokens specifically to keep continuous.

This is production wiring over verified machinery, not new risky capability. The MPS generator state
round-trips bit-identically through `torch.save`/`set_state`, fresh and mid-stream, and 23-01 turned
that measurement into a committed test.

Output: the seam in `scripts/teach_persona.py`, and `tests/test_phase23_resume.py`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → recorded evidence | `refuse_if_exists` exists because an arm's outputs are recorded evidence once written. A resume inverts that for three targets and must not invert it for the fourth. |
| checkpoint file → the ε label | A resume that restored the wrong state, or spanned two arms, publishes an ε describing a composition that never ran. |
| CPU smoke run → MPS long run | 5,056 B vs 44 B generator state; a reachable operator mistake torch refuses with a message naming no arm and no file. |
