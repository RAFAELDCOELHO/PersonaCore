**Why this is a new constant and not an edit.** `CONTROL_NOISE_FLOOR = 0.05357142857142849` is a
CORRECT measurement of the OLD control protocol — 8 random windows per step from a 51.94%-replay bin,
teaching loss weight `0.4342`, `grad_clip = 1.0` binding on 19 of 25 steps. It is not falsified; it
is RE-SCOPED. Editing it in place would destroy a true reading and would break
`test_budget_constants_re_derive`, which recomputes it from `results/phase23_control_floor.json`.
So the original stays byte-unchanged with a dated continuation naming what re-scoped it, and the new
floor lands beside it — the repository's retract-in-place register, applied unchanged.

**The one trap in that register, and it is a substring trap.** The continuation is supposed to be
evidence-rich, and an executor writing it would naturally QUOTE the constant it is re-scoping. But
`test_a_hand_edited_floor_is_detected` asserts `source.count("CONTROL_NOISE_FLOOR = <repr>") == 1`,
and that needle is a SUBSTRING of `MATCHED_CONTROL_NOISE_FLOOR = <same repr>`. So there are two ways
to break a currently-green guard here — quoting the literal assignment in prose, and a measured
matched floor whose `repr` happens to equal the original's — and the plan forbids weakening the
test. Both are handled below, the second with a named sanctioned repair.

**Why this file may be edited at all.** 23-09 deliberately did NOT register
`scripts/mitigation_budget.py` as a `prereg_artifact=`. Being named `mitigation_*.py` makes it
PROTECTED (it joins `_GATE_MODULES`, so the import ceiling and the rule/emission split police it) and
confers NO freeze; only a hand-written explicit path reaching `_assert_ordering_holds` confers one.
`test_the_budget_module_is_protected_but_not_frozen` makes that a checked property. This plan is the
first consumer of that middle ground and must leave it intact.
