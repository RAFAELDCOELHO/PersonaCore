<objective>
Build the ISO-04 adapter-swap canary in both layers and the generation modes of
`scripts/phase17_isolation.py`: one fresh process per sweep, four sweeps total (three adapters plus
the adapter-off column), each writing raw completions plus a live-weights `lora_B` digest, the
artifact file's own digest, and an explicit `adapter_enabled` flag to disk.

Purpose: ISO-04. All three personas share identical `lora_` key sets, identical shapes and an
identical `lora_config`, so every audit in `load_adapter_weights` — keys, shape/dtype and scale —
passes for the *wrong* artifact. The load path is structurally silent about adapter identity. Plan
17-04 confirmed on synthetic records what a silent no-op actually produces; this plan builds the two
guards that make it impossible to reach a report.

Output: the canary, the sweep and training modes, and mutation-proof that both layers fire.

**Task budget note.** This plan carries four tasks rather than the usual two or three. The split is
W9's, and the alternative is worse: `build_parser` is what makes a single process structurally
incapable of running two sweeps, and the bodies it dispatches to have to live in the same file for
that guarantee to mean anything — so a sibling plan would have to modify
`scripts/phase17_isolation.py` in the same wave, which the file-ownership rule forbids. Tasks 2 and 4
are light; Tasks 1 and 3 are the substantial ones.
</objective>

records, plus the artifact file digests recorded beside them.

`scripts/personalize_demo.py:448` and every future consumer rather than only this driver. That is a
real advantage and it is being declined, not overlooked.

It is declined because `load_adapter_weights` legitimately supports **re-applying an identical
adapter onto the model it came from**, and a "must differ" assertion at the choke point would refuse
it. The measured case is `tests/test_lora_artifact.py:257`
(`test_real_slim_two_artifact_load_cpu`): it nudges `lora_B` at :247, exports that model's own

and the assertion fires on a committed v2.0 test that is testing the export/load round-trip
correctly. `REAL_SLIM` is `checkpoints/model_slim.pt`, which exists in this tree, so its `skipif`
does not engage and the test runs locally.

The general principle: a same-adapter re-apply is a valid use of the library call, so "the adapter
resident after this load must DIFFER from the one before it" is a **Phase 17 run contract**, not a
library invariant. It belongs with the run. Record this reasoning — and the tradeoff being declined —
in the docstring, so W5 is not reopened as an unexamined simplification and is not re-decided from
the same wrong premise.
