| sweep process → report process | The recorded JSON is the only evidence that four distinct runs happened |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| TH-17-18 | Spoofing | silent substitution of the wrong adapter | mitigate | Two layers: in-process `_prove` that a `lora_B` changed and none is all-zero; cross-process `_prove` of pairwise-distinct live digests inside `--report`, before scoring. Both mutation-proved |
| TH-17-19 | Tampering | half-applied adapter leaving a corrupted model | mitigate | `load_adapter_weights` audits keys, shape/dtype and scale BEFORE any tensor is copied; never `model.load_state_dict(..., strict=False)` |
| TH-17-20 | Elevation of Privilege | pickled `.pt` code execution | mitigate | Adapters read only through `personacore.checkpoint.load_adapter` at `weights_only=True`; no direct `torch.load` on a shareable artifact (ASVS V5) |
| TH-17-21 | Tampering | the base column drifting from the adapter sweeps | mitigate | One `SHARED_ARM_CONFIG` object, one `forbid_ids` mask recorded by sha256 per sweep, `question_seed(index)` identical across all four, `adapter_disabled` rather than a second model |
