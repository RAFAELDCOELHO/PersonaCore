<objective>
Make the test suite safe to run **during** a 4.5–6.3 day GPU sweep, and commit the `pmset` revert as a
verifiable step rather than a promise.

Purpose: during the sweep the machine's MPS device is saturated. Every MPS-parametrized node id is
gated on `torch.backends.mps.is_available()`, which is **TRUE** at that moment — so 42 device-touching
legs will run and contend, and a contention failure is indistinguishable from a genuine one. D-44's
skip must be **loud**: a reason naming the sweep, and a skip count stated in advance so it can be
compared rather than trusted. The silent alternative — MPS legs quietly lost inside a green count — is
the failure `23-VALIDATION.md` already names as Pitfall 1.

And `sudo pmset -a sleep 0 disksleep 0 powernap 0` is a system-wide privileged change to the
developer's own machine. It must be reverted to the measured prior values, and the revert must be a
step this phase can verify, not something someone remembers six days later.

Output: `scripts/phase25_venue.py`, a `sweep_is_active()` helper in `tests/conftest.py` reading one
environment variable, two edits at the composition points, and `tests/test_phase25_venue.py`.
</objective>
