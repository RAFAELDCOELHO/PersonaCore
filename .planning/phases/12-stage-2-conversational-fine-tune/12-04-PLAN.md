<pre_registration>
## PRE-REGISTRATION BLOCK (locked NOW, before any smoke number exists)

These are USER DECISIONS (CONTEXT D-01..D-07 + user-confirmed lock resolutions). The driver
must encode them as constants verbatim; Task 1 commits the driver BEFORE Task 2 runs anything.

1. **Frozen dialogue-val gate policy (Pitfall 3):** dialogue val PPL = `masked_perplexity` on
   `data/dialog_val.bin` + `data/dialog_val_mask.bin`, block 256, forbid_ids =
   `undecodable_ids_mask` (dead ids forbidden; role ids 8185-8187 are decodable and never
   forbidden). Every gate, every arm, all stages. In-loop val_loss (masked via `val_mask_bin`)
   gates best-checkpoint selection only — never a gate (user lock 3).

2. **Noise floor & k (D-05):** Stage 0b = one smoke config run twice (seeds 1337 / 2024) at the
   recalibrated budget. Δ_dialog = |end-of-run masked_perplexity(A) − (B)|; Δ_ret =
   |after-run retention_perplexity(A) − (B)| on the sub-bin. All margins = k×Δ with **k = 2,
   declared blind**: a deliberately conservative default chosen before any smoke result exists —
   no principled derivation is available at this budget (stated explicitly in the report). For
   EACH gate the report also records the counterfactual k the observed deltas would have
   required.

3. **Budget recalibration (D-03 + user lock 2):** Stage 0 = ONE calibration run (masked arm,
   LR 9e-5 mid-sweep, seed 1337, eval_interval 250, max_steps CAL_MAX_STEPS = 5000) with
   `extra_eval_fns={"dialog_ppl": ...}`. Candidate budget = **slope rule only** (TinyStories
   absolute band DROPPED): recommended SMOKE_STEPS = smallest step S (multiple of 250) where
   dialog_ppl improvement over the trailing 1000 steps < 15% of the improvement over the first
   1000 steps; if never flattens, SMOKE_STEPS = CAL_MAX_STEPS (recorded as capped). The locked
   `SMOKE_STEPS` constant is enforced run_ablations-style: SystemExit if
   |recommended − SMOKE_STEPS| > 250 ("update the constant and re-run"). **Budget validity
   check (user lock 2):** the Stage 0b floor is measured AT SMOKE_STEPS and doubles as a
   validity check — if Stage 1's masked-vs-unmasked separation |Δ| ≤ 2×Δ_dialog, that is a
   VIOLATED-GATE HALT per the D-07 exception, surfaced to the user immediately (user then
   directs: extend budget, or accept the D-01 tie→masked verdict).

4. **Instability / non-monotonicity gate (D-02 + user lock 1 + Pitfall 5):** a run is unstable
   iff (a) any NaN/Inf in its logged loss/PPL columns, OR (b) any interval-to-interval
   INCREASE in the run's `dialog_ppl` column (the deterministic per-interval sweep via
   `extra_eval_fns` — the run's own logging intervals) exceeding 2×Δ_dialog. Locked before
   Stage 0b produces the floor. **Pre-registered fallback (D-02):** if the floor makes the gate
   undefinable — operationally: 2×Δ_dialog ≥ (first-interval dialog_ppl − last-interval
   dialog_ppl of the Stage 0 run), i.e. margin ≥ total signal — the driver HALTS and the
   executor invokes the fallback: a blocking user checkpoint on the raw curves, stated
   explicitly in the report.

5. **Masking verdict (D-01):** two runs (masked vs unmasked training loss), same LR 9e-5, seed
   1337, SMOKE_STEPS. Both evaluated with the frozen policy (§1). Unmasked wins ONLY if its
   end-of-run dialogue PPL beats masked by MORE than 2×Δ_dialog; ties and sub-margin wins go to
   masked. (Subject to the §3 validity halt first.)

6. **Cold-start diagnostic (D-04):** rides the two Stage-1 runs. eval_interval = 25 through the
   whole run (cadence N=25; the first 10% of budget is the diagnostic window);
   `extra_eval_fns = {"role_norm_user": wte[8185] norm, "role_norm_assistant": wte[8186],
   "role_norm_system": wte[8187]}` (cheap reads — the expensive retention fn is NOT attached at
   this cadence; retention measured before/after the run by the driver). Escalation trigger
   (mechanical): NaN/Inf in any logged column within the first 10% of intervals, OR val_loss at
   the 10%-of-budget interval > val_loss at the first logged interval (no net recovery from the
   cold-start window). Trigger ⇒ HALT + surface (D-07 exception); mitigation (row reinit to
   live-row mean / targeted warmup) is chosen at escalation time and must be evaluated against
   the un-mitigated run's numbers. No mitigation is built unless triggered.

7. **LR sweep (D-02):** ≤3 runs on the mask winner: LR ∈ {3e-4, 9e-5, 3e-5} (pretrain-peak ×1,
   ×0.3, ×0.1), seed 1337, SMOKE_STEPS, eval_interval 250, extras = {dialog_ppl}. The 9e-5 arm
   REUSES the Stage-1 winner run ONLY if config-identical including eval_interval — Stage-1
   runs use eval_interval 25, so by default the 9e-5 arm is run fresh at eval_interval 250
   (record whichever applies in the report; the reuse rule is pre-registered here either way).
   Gates per arm: (a) retention: after-run sub-bin retention_perplexity − step-0 anchor
   (retention_anchors.json) > 2×Δ_ret ⇒ retention collapse ⇒ arm fails; (b) instability per §4.
   LR* = lowest end-of-run dialogue PPL among passing arms. Zero passing arms ⇒ HALT.

8. **λ sweep (EWC-03, discretion pre-registered):** 5 runs on the LR* arm: λ ∈ {0.01, 0.1, 1,
   10, 100} (decade grid centered on 1 — the Fisher is mean-normalized so λ reads as stiffness
   relative to an average parameter, collapsing the literature's 0.1–10⁶ spread toward O(1));
   λ=0 reference = the LR* run itself, reused (identical config by D-03 construction). extras =
   {dialog_ppl, retention_ppl (per-interval on λ arms), ewc_penalty = float(penalty(m))},
   eval_interval 250. **λ\* rule:** largest λ whose end-of-run dialogue PPL is within
   2×Δ_dialog of the λ=0 arm's. **Demonstrability guard:** retention(λ*) must beat
   retention(λ=0) by MORE than Δ_ret; if no λ satisfies both, the finding "EWC not demonstrable
   at this budget" is surfaced at the D-07 checkpoint — never massaged. **Boundary-extension
   rule:** λ* on a grid endpoint ⇒ extend one decade that direction, run one extra arm,
   re-apply the rule before locking.

9. **Halt discipline (D-07):** pre-registered rules auto-proceed stage-to-stage. Any violated
   gate (instability, retention collapse, cold-start trigger, budget-validity, fallback
   condition) raises SystemExit naming the gate and the numbers — the executor STOPS the
   sequence and surfaces it to the user right then, never bundling it into the final report.
</pre_registration>
