## The ladder IS `run_fairness_control`, parametrized (RESEARCH, Ladder wiring)

The distance-~30 row is `run_fairness_control` with a substituted statement map — same 216
questions, same 9 draws, same scorer, same prompt builder. Building it that way makes cross-rung
parity structural rather than asserted, and makes D-15's proxy check a direct subtraction. Reuse the
committed pieces; do not write a second draw loop. A duplicated draw loop is how two arms silently
stop being paired.

## D-13, and why the top rung is a re-run and not a citation

The top rung is the fairness control **re-run POST-FIX** (~12 min against the ladder's ~80), with
the delta against the committed number reported as a **measurement of PERS-05's impact** rather than
a silent assertion that it did not matter. This revises an earlier decision to reuse Phase 14's
number as-is; the revision is recorded, not overwritten.

**The top rung can never be arm B.** PERS-01 requires the ladder recorded before any comparison is
scored, so a top rung taken from the comparison would be circular.

**The threshold anchor stays the COMMITTED number.** The re-run's delta is *reported*; it never
feeds `LADDER_FLOOR_*` or `LADDER_CELL_PASS_K`. Re-anchoring to it would set the gate after seeing
data.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| committed driver → produced report | A report whose text is written after the numbers is a report written to fit them |
| recorded verdict → a later run | Re-running the driver over a committed verdict destroys the evidence the phase rests on |
| ladder cell → the floor it is compared against | Different `n` or different draw counts make the comparison meaningless while still producing a number |
