## Wall clock and how to launch

Four-arm run: `270 x (2.181 + 3.183 + 3.185 + 0.009) s ≈ 38.5 min`, consistent with the citable
**~39 min (realistically 35-44 min)**. **Never quote "39.2 min"** — arm A measured twice over the
same 30 questions gave means 2.654 vs 2.380 (11.5% apart), exceeding the intra-run 95% CI (±4%), so
the intra-run interval understates real uncertainty and must never be quoted alone.

The sweep adds 6 dilution cells + 1 overwrite cell on arm B at ~3.18 s/question.

**The Bash tool's maximum timeout is 10 minutes.** Every condition must be launched in the
background with output appended to `results/phase16_persistence_raw.log`, then polled.

Arm cost is governed by **when each arm stops, not by how much compute each step does** — a
prediction that arm C would be faster than arm A because it skips the LoRA matmuls was FALSIFIED
(arm C is 30% slower: the adapted model hits `STOP_IDS` early because it answers and stops, while
the base rambles to the 48-token cap). Recorded so a slow arm C is not read as a fault.

## The predicted outcome, recorded before the run

CONTEXT.md §Measured Facts records Phase 14's per-fact adapter rates with **zero zero-rate facts in

  threshold after seeing a number.
