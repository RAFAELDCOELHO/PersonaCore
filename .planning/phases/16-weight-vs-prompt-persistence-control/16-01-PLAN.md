<threat_model>
## Trust Boundaries

This phase has no network surface, no user input, and no deployment. The trust boundary that
matters is **between a published number and the evidence that number claims to rest on** — an
artifact crossing from "measured" to "committed and cited".

| Boundary | Description |
|----------|-------------|
| pre-registration → results | A gate committed *after* the numbers it judges is not a gate |
| working tree → CI | A guard that resolves locally but errors in CI is enforcement theater |
| declared dependency set → installed environment | A silent install falsifies STAT-04's zero-new-dependency claim |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-01 | Tampering | `scripts/erasure_gate.py` pre-registration ordering | mitigate | Task 2: `git merge-base --is-ancestor` on the DAG, never committer timestamps — a rebase can rewrite dates but not ancestry |
| T-16-02 | Repudiation | PREREG-02 guard in CI | mitigate | Task 1: `fetch-depth: 0`. Task 2 asserts `--is-shallow-repository == false` and fails rather than skips, so a blind guard is loud |
| T-16-03 | Spoofing | The guard's own coverage set | mitigate | Task 2's `assert checked` — the guard cannot pass by matching nothing |
| T-16-04 | Tampering | `PREREG_COMMIT` literal | mitigate | Task 2's second test asserts the SHA resolves AND touches `scripts/erasure_gate.py`; full 40-char SHA, never the ambiguous short form |
| T-16-SC | Tampering | dependency surface (npm/pip/cargo) | mitigate | **This phase installs zero packages** (STAT-04). Task 3 pins `pyproject.toml` by sha256 so an install is a red test, not a quiet diff. No package legitimacy audit is required because there is nothing to audit; reaching for a package is the signal the design went wrong |
</threat_model>
